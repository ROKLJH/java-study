# 로드맵과 지금까지의 결정 (2026-11-16 정리)

## 최종 목표
친구들과 노는 마인크래프트 Java Edition 서버를 만들고, 원하는 기능을 직접 개발한다.

## 만들고 싶은 기능 (첫 아이디어)
1. **인벤토리 보호권**: 인벤토리에 보호권이 있는 상태로 죽으면 1장 차감되고, 장비와 아이템이 유지된다.
   - 바닐라 아이템 + `custom_data` 컴포넌트로 표식, 사망 이벤트 / Mixin, 리스폰 시 인벤토리 복사
2. **워프 포인트** (원신식 순간이동 포인트): 포인트를 해금하고 해금된 곳끼리 이동한다.
   - Brigadier 명령어, PersistentState 저장, 텔레포트, 상자형 GUI
3. **차원 포탈**: 야생 ↔ 마을(안전구역) 왕래
   - 데이터팩으로 커스텀 차원, 이벤트로 블록 파괴/PvP 금지, 프레임 구조물 + 파티클로 포탈 연출
4. **머리 위 이모티콘**
   - Text Display 엔티티를 플레이어에 탑승, 리소스팩 커스텀 폰트로 이미지 이모티콘

추천 개발 순서: 워프(명령어 버전) → 보호권 → 마을 차원/안전구역 → 이모티콘

## 배운 핵심 개념
- 서버를 꾸미는 방식: 데이터팩 / 플러그인(Paper) / 모드(Fabric, NeoForge)
- **서버 전용 모드**로 설계하면 친구들은 아무것도 설치하지 않고 접속할 수 있다. 위 4개 기능은 모두 서버 전용으로 가능하다.
- Fabric은 마인크래프트 내부 코드에 붙기 때문에 버전이 바뀌면 수정(포팅)이 필요하다. Paper API는 상대적으로 안정적이다.
  - 대응: 버전 고정, Fabric API 이벤트 우선 사용, Mixin 최소화, **게임 로직과 마인크래프트 코드 분리**
- 월드는 새 버전으로 업그레이드할 수 있다 (되돌리기는 불가 → **백업 필수**). 새 지형은 안 가본 청크에만 생긴다.
  - 내가 직접 저장한 데이터(워프 목록 등)의 형식 호환은 내가 책임진다.
